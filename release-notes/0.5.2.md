# TermTile 0.5.2

A fix for the menu panel's height, and a correction to what 0.3.1 claimed.

- **Fixed the menu panel's empty bands, for real this time.** The panel's window kept the tallest
  height it had ever needed, so once it had shown a taller state the shorter content afterwards sat
  centred in an oversized window with transparent gaps above and below. The window now follows its
  content back down. Measured on the signed build by driving the Session-tint toggle, which changes
  the panel's height without changing anything else: the gap above and below the content stayed at
  14 pt across a 114 pt content change, where it previously grew to 70 pt. Verified over three
  cycles and across closing and reopening the panel.

- **0.3.1's release note for this was wrong, and 0.3.2's fix was inert.** 0.3.1 said "the panel now
  fills its window from the top, so no gap shows" — it did not; the extra height is outside the
  SwiftUI view, so no layout modifier could reach it. 0.3.2 then asked AppKit for the content height
  and silently did nothing, because every view in the panel's tree reports a zero fitting size and a
  negative intrinsic size, so its own guard returned early on every open. The height now comes from
  SwiftUI, which is the only part of the system that knows it.

- **The Session-tint summary now updates when you open the menu.** It was computed once per launch
  and then frozen, so it could sit there reading "1 tinted · 7 not:" while all eight sessions were
  in fact painted correctly — and flipping the toggle off and on made the line vanish until the app
  was restarted. It re-reads on every open now, which costs nothing: the number comes from a value
  TermTile already has, not from a fresh look at your screen.
